# AI Usage Log — Implementasi Modul PMB, KRS, Jadwal, Nilai, Transkrip, Keuangan, & Presensi SEVIMA-Mini (Minggu 3–12)

Catatan ini mendokumentasikan penggunaan asisten AI selama perancangan skema database, implementasi REST API, perbaikan arsitektur NIM generator berbasis database lock (Minggu 4), Modul KRS bagian 1–2 (Minggu 5–6), Modul Jadwal & Ruangan bagian 1–2 (Minggu 7–8), Modul Nilai & Transkrip bagian 1–2 (Minggu 9–10), Modul Keuangan (SPP) (Minggu 11), serta **Modul Presensi (QR Code)** (QR ber-JWT 15 menit, rotasi `jti`, geofencing, rate limiting, adaptor nyata `DBPresensiAdapter`, ekspor Excel `.xlsx`, & AI Attendance Insights di Minggu 12). Versi terstruktur sesuai format silabus + kerangka **OPAR** (*Observe, Plan, Act, Reflect*) tersedia lengkap pada [prompts/ai-usage-log.md](../prompts/ai-usage-log.md).

## Kepatuhan AI-First Charter

1. **Perlindungan Data Pribadi (PII & Nilai Mahasiswa):** Nilai mahasiswa adalah data pribadi sensitif. Seluruh prompt, fixture pengujian, dan contoh skema hanya menggunakan data *dummy* fiktif (`"Budi Santoso"`, `"Rina Pratama"`, `"Sari Wulandari"`). Tidak ada nilai atau data pribadi mahasiswa asli yang dikirim ke AI.
2. **Prinsip Validasi:** Tidak ada kode hasil generasi AI yang langsung disalin tanpa ditinjau, diperiksa kesesuaian arsitekturnya, disesuaikan dengan pustaka target (SQLAlchemy 2.0, Pydantic v2), dan diuji melalui Alembic serta `pytest`.

## Detail Prompt Terbaik & Evaluasi Kritis

### Prompt Terbaik 1 — Skema SQLAlchemy 2.0 & Migrasi Rollback Aman
> "Desain skema database PMB untuk sistem akademik menggunakan SQLAlchemy 2.0 (`DeclarativeBase`, `Mapped`, `mapped_column`) dengan tabel `program_studi`, `jalur_masuk`, `calon_mahasiswa`, dan `nim_counter` (`tahun`, `kode_prodi`, `last_number`). Sertakan migrasi Alembic `upgrade()` dan `downgrade()` yang aman terhadap urutan foreign key, dan jelaskan constraint yang ditegakkan di DB vs Pydantic."

- **Evaluasi Kritis:** Memastikan kolom `phone` bertipe `String(15)` (bukan `Integer`), `PRAGMA foreign_keys=ON` aktif di SQLite, dan `create_constraint=True` dipasang pada `Enum` status agar constraint tersimpan eksplisit di skema DB.

### Prompt Terbaik 2 — Endpoint OOP `PMBService` & Kontrak HTTP Code
> "Refaktor service layer menjadi kelas OOP `PMBService` dan router tipis `/api/pmb/*` lengkap dengan anotasi OpenAPI `responses={...}`. Pisahkan HTTP status code pada `PUT /approve/{id}` dan `PUT /reject/{id}`: `404` bila ID tidak ada, `409 Conflict` bila konflik status (`StatusTidakValid`: bukan `pending` atau sudah `approved` saat reject), dan `400` bila data tidak valid untuk NIM (`DataNIMTidakValid`)."

- **Evaluasi Kritis:** Mencegah pencampuran kesalahan validasi payload (`400`) dengan pelanggaran alur status (`409`), sekaligus mendokumentasikan setiap skenario respons di Swagger UI `/docs` dan ReDoc `/redoc`.

### Prompt Terbaik 3 — NIM Generator Tanpa `threading.Lock()` (Database-Level Locking)
> "Refactor `generate_nim(tahun, kode_prodi, db)` agar tidak menggunakan `threading.Lock()` atau `MAX(nim) + 1`. Gunakan tabel `nim_counter` dengan `with_for_update()` untuk MySQL/PostgreSQL serta `BEGIN IMMEDIATE` dan `PRAGMA busy_timeout` untuk SQLite. Pastikan `generate_nim()` hanya memanggil `db.flush()` (bukan `db.commit()`), terbungkus satu transaksi bersama `PMBService.approve()`, dan lindungi dengan constraint `UNIQUE` + retry loop."

- **Evaluasi Kritis:** Jika `generate_nim()` memanggil `db.commit()` sendiri, kegagalan penyimpanan `calon_mahasiswa` tetap menyisakan kenaikan counter (nomor urut hilang/melompat). Menyatukan transaksi di `PMBService.approve()` dengan `db.flush()` memastikan sifat atomik (*all-or-nothing*).

### Prompt Terbaik 4 — Rantai Validasi KRS & Query Prasyarat Anti-Jebakan (Minggu 5)
> "Dengan model `SkalaNilai`, `MataKuliah`, `prerequisite`, `KRS`, dan `KRSDetail` pada SQLAlchemy 2.0, implementasikan pola Chain of Responsibility (`Validator(ABC)`, `ValidationResult`, `KRSContext`, `build_chain`) untuk urutan `DuplicateValidator -> SKSValidator -> PrerequisiteValidator -> ConflictValidator`. Gunakan rumus irisan interval (`jam_mulai < jam_selesai`), query `NOT EXISTS` dengan bobot `skala_nilai >= 2.0` (`C`) di `semester < aktif`, serta `KRSManager.add_course()` yang mengunci baris KRS dalam satu transaksi."

- **Evaluasi Kritis:** Menolak perbandingan string nilai huruf (`nilai >= 'C'`) yang keliru di SQLite/MySQL dan memastikan kuliah bersambung (misalnya `08:00–10:30` dan `10:30–12:30`) diizinkan dengan operator `<`, serta membuktikan penghapusan *full table scan* lewat [docs/EXPLAIN_PRASYARAT.md](EXPLAIN_PRASYARAT.md).

### Prompt Terbaik 5 — State Machine KRS, Optimistic Lock, Hypothesis & CSP Guardrail (Minggu 6)
> "Enkapsulasi state machine `KRS` memakai enum `Actor` dan kamus `TRANSITIONS` pada `app/models/krs.py`, tambah migrasi `0004` (`version`, `krs_log`, `notifikasi`), serta implementasikan `submit_krs`, `approve_krs`, dan `revise_krs` atomik (1 commit + rollback penuh) dengan otorisasi PA `403` vs konflik status/versi basi `409`. Tambahkan test `hypothesis` (`max_examples=1000`) yang menguji `SKSValidator` & `ConflictValidator` (oracle `_slot` independen), ke-28 transisi ilegal `itertools.product`, dan `KRSRecommender` CSP dengan guardrail validator."

- **Evaluasi Kritis:** Memastikan tidak ada `krs.status = ...` langsung di service/router, memaksa naik `version` lewat `_sentuh_krs()` setiap `add_course`/`remove_course`, menghindari tautologi *property test* dengan oracle independen `_slot()`, serta menjaga prinsip bahwa rekomendasi CSP selalu divalidasi ulang oleh rantai validator sebelum keluar ke API.

### Prompt Terbaik 6 — Detektor Bentrok 3 Dimensi, Anti-Bug Klasik AI, & `SchedulingService` (Minggu 7)
> "Bangun model `Ruangan`, `Dosen`, `Kelas`, `Jadwal` + `krs_detail.kelas_id` (`0005`), fungsi `detect_naive` ($O(n^2)$) dan `detect_schedule_conflict` (*Grouping + Sort & Sweep* $O(n \log n + k)$) dengan interval setengah-terbuka `[mulai, selesai)` bertipe `datetime.time`, `Conflict(frozen=True)` khusus `'room_conflict'` & `'lecturer_conflict'`, serta `SchedulingService` dengan `cek_kapasitas(max(kuota, terdaftar))`, lock berurutan `Ruangan -> Dosen`, `BEGIN IMMEDIATE`, dan router `/api/jadwal` (`422` validasi / `409` detail konflik)."

- **Evaluasi Kritis:** Menutup seluruh 5 bug klasik AI pada deteksi bentrok, menjaga kompatibilitas mundur *expand-contract* pada `matakuliah` sehingga 83 tes PMB/KRS tidak regresi, menguji ekuivalensi sweep vs naif lewat 500x Hypothesis *differential testing*, serta mendokumentasikan penundaan *Interval Tree* secara empiris di `ADR-011` (`2.40–2.84 ms` vs `25.94–39.61 ms` pada `n=600`).

### Prompt Terbaik 7 — Observer Pattern + Transactional Outbox & Integrasi State Machine KRS (Minggu 8)
> "Bangun `ScheduleSubject` (anti-duplikat `attach`, `notify` terisolasi `try/except`), 3 observer (`StudentObserver`, `LecturerObserver` dosen lama+baru, `AdminObserver`) lewat `LogChannel` (`EMAIL`/`SMS`/`PUSH` + idempotency key `{event_id}:{penerima}:{ch}`), serta tabel `Outbox` (`0006`) + `OutboxDispatcher` (`SKIP LOCKED`, max 5 retry -> `FAILED`) yang hanya dijalankan sesudah `commit()`. Tambah `Actor.SISTEM` pada state machine KRS (48 kombinasi = 6 sah + 42 ilegal) dan hubungkan `KRSInvalidator` ke transaksi tunggal `SchedulingService.update/delete`."

- **Evaluasi Kritis:** Memisahkan penulisan `Outbox` & invalidasi KRS di dalam transaksi SQL utama dari eksekusi `OutboxDispatcher.run()` pasca-`commit()` mencegah notifikasi palsu saat *rollback* dan menjaga jadwal tetap tersimpan meskipun *gateway* notifikasi gagal. Pemasangan singleton observer dengan `ContextVar` sesi menghindarkan bug memori `attach()` per HTTP request sekaligus tetap bekerja di database in-memory pengujian.

### Prompt Terbaik 8 — AI Rescheduling Guardrail 4 Lapis, Conflict Resolver UI, & iCalendar RFC 5545 (Minggu 8)
> "Buat AI Rescheduler (`hitung_slot_tersedia`, `bangun_prompt`, `parse_saran` aman JSON, guardrail 4 lapis `saring_saran` memakai `detect_schedule_conflict` kandidat `id=-1`, fallback heuristik offline, dan `apply_saran` satu pintu via `SchedulingService.update`). Lengkapi router `/api/jadwal` dengan `/resolver` HTML UI, `/suggestions`, `/apply`, proteksi `require_admin` (`X-Role: admin -> 403`), serta ekspor `GET /api/mahasiswa/{nim}/jadwal.ics` sesuai RFC 5545 (`CRLF`, `TZID=Asia/Jakarta`, UTC `UNTIL`, kenaikan `SEQUENCE`)."

- **Evaluasi Kritis:** Pengujian deterministik menggunakan `FakeLLM` memastikan ruangan fiktif, kapasitas kurang, dan slot bentrok ditolak total oleh validator deterministik. Uji fallback heuristik juga langsung menangkap bug halus pada `rfind("]")` yang kini diganti `json.JSONDecoder().raw_decode()`.

### Prompt Terbaik 9 — Spesifikasi Anti-Ambiguitas, Kalkulator `Decimal` Murni, & Audit `GradeService` (Minggu 9)
> "Sebelum menulis kode, sebutkan semua ambiguitas atau kontradiksi di spesifikasi (khususnya `>= D (2.0)` vs skala bobot `D=1.0`/`C=2.0`). Perbarui `skala_nilai` memakai `Numeric(3,2)` + `lulus`, buat `grade_history` + view `v_riwayat_nilai` (`0007`) merujuk `krs_detail.id`. Implementasikan fungsi murni `app/domain/gpa.py` (`Decimal` `ROUND_HALF_UP` di akhir, terbaik per `kode_mk` dulu baru saring `lulus`), `NilaiRepo` + CTE SQL `ROW_NUMBER()`, `GradeService` (`is_pengampu` `403`, `PresensiPort` `>=75%`, wajib alasan edit), UI `/api/kelas/nilai-form`, serta 12+ kasus & 3 properti Hypothesis."

- **Evaluasi Kritis:** Mengungkap kontradiksi aturan lulus `D` vs `2.0` (`C`) secara eksplisit melalui ADR-016 (serta membuktikan selisih `3.08` vs `2.67` pada test), menghindarkan bug *banker's rounding* `3.125 -> 3.12` dengan `ROUND_HALF_UP` (`3.13`), memvalidasi kebenaran SQL CTE vs fungsi murni Python, dan menjaga seluruh audit trail `GradeHistory` berada dalam satu transaksi atomik bersama pembaruan `krs_detail.nilai`.

### Prompt Terbaik 10 — `get_transcript(nim)`, Predikat Kelulusan, Template Resmi Jinja2, & ReportLab PDF (Minggu 10)
> "Lanjutkan Modul Nilai & Transkrip bagian 2: perluas fungsi murni `app/domain/gpa.py` (`bangun_ringkasan_transkrip`, `tentukan_predikat`, `format_label_semester`), tambah `GPACalculator.get_transcript(nim)` compute-on-read, buat template Jinja2 resmi bergaya ijazah (`app/templates/transkrip.html`), implementasikan `TranscriptPdfRenderer` dengan `ReportLabTranscriptRenderer` (logo vektor, biodata, tabel MK per semester `repeatRows=1`, total SKS/IPK/predikat, TTD Dekan, XML escaping, tanpa `Table([])` kosong), endpoint JSON/HTML/PDF `/api/mahasiswa/{nim}/transkrip*`, demo 3 semester Dina (`2025001-0004`), serta tes escaping XSS & parsing PDF `pypdf`."

- **Evaluasi Kritis:** Memilih `ReportLab` Pure-Python daripada WeasyPrint menghindarkan error pustaka native Windows sekaligus menjaga keselarasan data dari satu model `TranskripAkademik`. Ekstraksi teks `pypdf.PdfReader` langsung pada response PDF dan simulasi 4 semester (`>= 2` halaman + edit nilai `PUT /nilai` → update IPK/PDF seketika) memastikan hasil akhir teruji end-to-end.

### Prompt Terbaik 11 — Modul Keuangan (SPP), Keamanan Webhook HMAC, APScheduler, Blokir KRS, & AI Financial Insights (Minggu 11)
> "Bangun Modul Keuangan (SPP) di SEVIMA-Mini: domain murni `Decimal` (`app/domain/keuangan.py`), 3 tabel `payment_method`, `billing` (`unpaid`/`partial`/`paid`/`overdue`), & `payment` (`0008`), `BillingService` (generate tagihan per prodi + due date 2 minggu, cicilan `partial -> paid` atomik, denda 0.5%/hari maks 10%, webhook HMAC-SHA256 `compare_digest` + idempotency `transaction_id` + email receipt pasca-commit), `BillingScheduler` APScheduler, blokir KRS `403` untuk penunggak, dashboard HTML `/api/keuangan/dashboard`, serta `FinancialReportService` analisis CSV ke JSON."

- **Evaluasi Kritis:** Pemisahan perhitungan deterministik (`analisis_keuangan_csv`) dari narasi mencegah kesalahan angka atau halusinasi pada laporan keuangan, sementara eksekusi email receipt pasca-commit menjaga transaksi pembayaran tetap kokoh meski layanan email terganggu. Pengujian end-to-end dengan `curl.exe` membuktikan alur nyata: tunggakan memblokir KRS (`403`) → webhook HMAC melunaskan tagihan + mengirim receipt (`200`) → dashboard real-time terbarui → KRS langsung terbuka (`201`).

### Prompt Terbaik 12 — Modul Presensi (QR Code), JWT Anti-Replay, Geofence, Rate Limit, `DBPresensiAdapter`, Excel Export, & AI Insights (Minggu 12)
